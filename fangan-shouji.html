怎么把消息变成看板条目

企业微信自建应用 + 云函数 + GitHub，全程你只发一句话

1先看清一件事

微信（个人）没有给外部开放的收消息接口，所以“我直接听你微信”这条路不存在。能做的是：把消息送进一个我能读的地方，再由我整理进看板。

1你在企业微信里给“随手记”应用发一句：商机备忘-名城-OA-和戴主任确认预算口径
2企业微信把这条消息推到你自己的云函数（公网 HTTPS 地址）
3云函数验签、解密，把这条追加到 GitHub 仓库的 shouji-queue.json
4我读取队列，按口令写进常记/笔记/日记，你手机上刷新看板就能看到
你全程只做第 1 步。第 2–4 步配一次，之后一直自动跑。

2需要准备什么

要什么从哪来难度
企业微信管理员权限（或让 IT 代配）企业微信管理后台 → 应用管理 → 自建权限本身最难
一个公网 HTTPS 地址腾讯云 SCF / 阿里云 FC 的 API 网关，自带域名开通即用
GitHub 细粒度令牌GitHub → Settings → Developer settings → Fine-grained tokens只勾这一个仓库的 Contents 读写
三个随机串企业微信后台生成 Token、EncodingAESKey；企业 ID 在“我的企业”复制粘贴
费用：云函数按调用计费，你一天发 20 条，一个月也在免费额度内，基本 0 元。

3企业微信后台怎么配

以下步骤需要管理员账号，或让 IT 照做。

① 建自建应用

  • 管理后台 → 应用管理 → 应用 → 自建 → 创建应用
  • 名字填「随手记」，可见范围选你自己
  • 建好后记下 AgentId、Secret（主动推送时才用）

② 开启接收消息

  • 进入该应用 → 接收消息 → 设置 API 接收
  • URL：先填云函数地址（下一步拿到），形如 https://xxx.apigw.tencentcs.com/release/shouji
  • Token、EncodingAESKey：点“随机获取”，两串都抄下来
  • 点保存时企业微信会立刻请求你的 URL 验证，所以要先把云函数部署好

③ 在微信里找到它

  • 企业微信 App → 工作台 → 「随手记」
  • 进去直接发文字即可；语音会以语音消息进来（要转文字需再加一步下载转写）

4云函数怎么部署

以腾讯云 SCF 为例，阿里云 FC 同理（入口函数名改成 handler）。

  • 新建函数：Node.js 18，类型选“事件函数”，触发器选 API 网关
  • 把下面的代码粘进 index.js（本页最下方可一键复制）
  • API 网关路径配 /shouji，方法允许 GET 和 POST，集成响应打开
  • 环境变量按下表填，保存后发布
变量名填什么
WECOM_TOKEN后台生成的 Token
WECOM_AES_KEY后台生成的 EncodingAESKey（43 位）
WECOM_CORP_ID企业 ID（ww 开头）
GH_TOKEN细粒度令牌（只给这个仓库 Contents 读写）
GH_REPOsuzhou-renshi/suzhou-renshi
GH_FILE可不填，默认 shouji-queue.json
令牌只给这一个仓库、只给 Contents 读写，不要给全仓库或账号级权限；一旦怀疑泄露，在 GitHub 一键吊销即可，不影响看板。

5云函数代码（可直接用）

// 企业微信「随手记」回调云函数（Node.js 18，腾讯云 SCF / 阿里云 FC 通用思路）
// 作用：接收企业微信自建应用的消息 → 追加写入 GitHub 仓库的 shouji-queue.json
// 环境变量：WECOM_TOKEN、WECOM_AES_KEY、WECOM_CORP_ID、GH_TOKEN、GH_REPO（owner/repo）、GH_FILE（可选）
const crypto = require("crypto");

const TOKEN = process.env.WECOM_TOKEN;
const AES_KEY = process.env.WECOM_AES_KEY;
const CORP_ID = process.env.WECOM_CORP_ID;
const GH_TOKEN = process.env.GH_TOKEN;
const GH_REPO = process.env.GH_REPO;
const GH_FILE = process.env.GH_FILE || "shouji-queue.json";

const sha1 = (s) => crypto.createHash("sha1").update(s).digest("hex");

function checkSig(sig, ts, nonce, encrypt) {
  if (!sig || !ts || !nonce || !encrypt) return false;
  const arr = [TOKEN, String(ts), String(nonce), encrypt].sort();
  return sha1(arr.join("")) === sig;
}

function decrypt(enc) {
  const key = Buffer.from(AES_KEY + "=", "base64");
  const iv = key.slice(0, 16);
  const d = crypto.createDecipheriv("aes-256-cbc", key, iv);
  d.setAutoPadding(false);
  let buf = Buffer.concat([d.update(enc, "base64"), d.final()]);
  const pad = buf[buf.length - 1];
  if (pad > 0 && pad <= 32) buf = buf.slice(0, buf.length - pad);
  const msgLen = buf.readUInt32BE(16);
  const msg = buf.slice(20, 20 + msgLen).toString("utf8");
  const receiveId = buf.slice(20 + msgLen).toString("utf8");
  return { msg, receiveId };
}

function pick(xml, tag) {
  const m = xml.match(new RegExp("<" + tag + "><!\\[CDATA\\[([\\s\\S]*?)\\]\\]></" + tag + ">"));
  return m ? m[1] : "";
}

async function gh(method, path, body) {
  const url = "https://api.github.com/repos/" + GH_REPO + path;
  const r = await fetch(url, {
    method,
    headers: {
      Authorization: "Bearer " + GH_TOKEN,
      Accept: "application/vnd.github+json",
      "User-Agent": "wecom-shouji",
      "Content-Type": "application/json",
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  if (r.status === 404) return null;
  if (!r.ok) throw new Error("GitHub " + r.status + " " + (await r.text()));
  return r.json();
}

async function appendItem(item) {
  const path = "/contents/" + GH_FILE;
  let data = { items: [] };
  let sha = null;
  const cur = await gh("GET", path);
  if (cur) {
    sha = cur.sha;
    try {
      data = JSON.parse(Buffer.from(cur.content, "base64").toString("utf8"));
    } catch (e) {
      data = { items: [] };
    }
  }
  data.items = data.items || [];
  data.items.push(item);
  if (data.items.length > 500) data.items = data.items.slice(-500);
  const body = {
    message: "随手记：" + (item.text || "").slice(0, 40),
    content: Buffer.from(JSON.stringify(data, null, 1), "utf8").toString("base64"),
  };
  if (sha) body.sha = sha;
  await gh("PUT", path, body);
}

exports.main_handler = async (event) => {
  const q = event.queryString || event.query || {};
  const method = (event.httpMethod || event.requestContext?.http?.method || "GET").toUpperCase();
  const raw = event.body || "";
  const body = event.isBase64Encoded ? Buffer.from(raw, "base64").toString("utf8") : raw;

  // 1) 企业微信后台「验证 URL」：解密 echostr 原样返回
  if (method === "GET") {
    const sig = q.msg_signature, ts = q.timestamp, nonce = q.nonce;
    const echo = decodeURIComponent(q.echostr || "");
    if (!checkSig(sig, ts, nonce, echo)) return { statusCode: 403, body: "bad signature" };
    const { msg } = decrypt(echo);
    return { statusCode: 200, headers: { "Content-Type": "text/plain" }, body: msg };
  }

  // 2) 收到消息：验签 → 解密 → 取正文 → 写队列
  try {
    const enc = pick(body, "Encrypt");
    const sig = q.msg_signature, ts = q.timestamp, nonce = q.nonce;
    if (!checkSig(sig, ts, nonce, enc)) return { statusCode: 403, body: "bad signature" };
    const { msg, receiveId } = decrypt(enc);
    if (CORP_ID && receiveId && receiveId !== CORP_ID) return { statusCode: 200, body: "success" };

    const text = (pick(msg, "Content") || "").trim();
    const from = pick(msg, "FromUserName");
    const msgType = pick(msg, "MsgType");

    if (text) {
      await appendItem({
        t: new Date().toISOString(),
        from,
        type: msgType || "text",
        text,
        src: "wecom",
      });
    }
    // 语音消息 MediaId 需另调接口下载转写（可选，后续可加）
    return { statusCode: 200, headers: { "Content-Type": "text/plain" }, body: "success" };
  } catch (e) {
    console.error(e);
    return { statusCode: 200, body: "success" }; // 避免企业微信重试风暴
  }
};

6消息怎么变成看板条目

我按口令判断写到哪里，和我平时在对话里用的是同一套：

商机备忘-单位-商机-内容 → 常记·商机下 笔记-分类-标题-内容 → 笔记看板 日常记录 … → 日记看板 联想 → 人物助记 业务在用 → 客户业务栏

没有口令的纯文字，我先放进“待归类”，下次对话时问你要归到哪，不会丢。

需要我这边配一个定时任务

  • 每小时（或每天两次）读一次 shouji-queue.json，把新条目落到对应看板并重新上线
  • 落完把队列标记为已处理，避免重复
  • 这个定时任务用平台的定时能力，不需要额外服务器

7这条路的风险与限制

企业微信消息回调需要公网 HTTPS，公司网络可能限制外网服务；如果用公司内网地址，外部收不到。稳妥做法是用你自己的云账号开一个函数，别走单位网络。
  • 语音消息默认只有 MediaId，要转文字得再调“获取媒体文件”接口 + 转写，可以做但多一步
  • 企业微信会重试回调，代码里已做幂等处理（失败也回 success，避免重复刷队列）
  • 图片/文件只存链接或 MediaId，不自动 OCR（要 OCR 可以后加）

8备选：邮箱通道（更快通）

如果你搞不定企业微信权限，还有一条今天就能通的路：

1手机邮箱 App 发一封给自己：主题随便，正文写口令 + 内容
2我用 IMAP 定时读这个收件箱（需要你给一个专用邮箱的授权码）
3同样按口令落板，多余邮件不进看板
优点：不需要企业微信权限、不需要公网服务。缺点：不如微信顺手，且要保管好授权码。

9现在可以先不配

你日常在外面跑，其实用对话也能达到八成效果：把一句话发给我（手机客户端或电脑），我直接落板。等这套通道配好，区别只是“不用打开客户端”。
